# 可视化渲染方向：用开源模型做实验四，可行吗？

> 2026-11-14　｜　结论先行：**可行，而且比纯手写建模更容易出效果；但“下载模型 + 套个查看器”拿不到高分，真正的工作量在资产管线、场景设计、交互和性能。**

---

## 一、结论与边界

### 可行的理由

1. 课程 PDF 明确把 **three.js / babylon.js / Cesium.js** 列为可选工具，也把“3D 数据、模型/产品、数字展厅”列为方向；
2. 开源模型（CC0/CC BY）质量远高于三周内手工建模的上限，能把时间省给光照、材质、交互；
3. 你已有实验一～三的相机、UI、测试、报告流水线，场景外壳可以复用；
4. 模型驱动的场景天然适合“导览 + 展台 + 标注”的叙事，答辩好讲。

### 不可行的做法

- 直接拿一个 GLB 丢进 `<model-viewer>` 或 three.js 示例页 → 评委会问“这是你做的吗”，工作量和技术含量都不够；
- 下 10 个风格不一的模型堆在白房间里 → 像素材展示，不像作品；
- 用 Sketchfab 上许可不明的模型 → 版权与学术规范风险；
- 不压缩直接塞 50MB Sponza → `file://` 打不开、答辩现场卡死。

**正确姿势**：外部模型只当“藏品/产品”，**展厅、灯光、材质调优、交互、后期、性能、叙事全部自己做**，并在 PPT/报告里把资产管线讲清楚。

## 二、先选项目形态

| 形态 | 画面 | 模型来源 | 工作量 | 风险 | 推荐度 |
| --- | --- | --- | --- | --- | --- |
| **数字展厅 / 虚拟博物馆** | 自建展厅 + 多件藏品 + 聚光灯 + 标注 + 导览 | Smithsonian、Poly Haven、NASA | 中 | 低 | ★★★★★ |
| **产品可视化 / 虚拟展厅** | 5 件产品，转台、拆解、材质配色、影棚灯 | Poly Haven、Khronos CC0 | 中 | 低 | ★★★★★ |
| **3D 城市地图** | OSM 建筑 + 地形 + 标签 + 漫游 | OSM / Cesium ion | 大 | 高（数据管线） | ★★☆☆☆ |
| **科学/工业数据可视化** | 点云、医学/流体数据、剖切 | 公开数据集 | 大 | 高（数据获取） | ★★☆☆☆ |

**推荐：把前两者合成一个「虚拟产品展厅」**——既有“数字展厅”的空间与叙事，又有“产品可视化”的精致度：

> 一座自建的美术馆中庭，陈列 5 件 CC0 设计藏品（复古相机、音箱、台灯、腕表、鞋/家具）。观众可第一人称漫游与环视，靠近展台自动聚焦；按 `E` 拆解（爆炸图）、按 `M` 切换材质/配色、按 `L` 切换展厅灯光（日光/黄昏/夜间/摄影棚）；顶部“导览模式”自动巡游；每件展品有标注热点与信息卡。

这条线同时命中评分点：场景设计、模型造型、贴图合理、光照、漫游环视、键鼠/菜单交互、脚本叙事。

## 三、渲染技术路线怎么选

| 路线 | 首屏时间 | 上限 | 风险 | 适合 |
| --- | --- | --- | --- | --- |
| **three.js + 自建场景/自定义 shader** | 1~2 天 | 高 | 低 | 3 周内要完成度（推荐） |
| 自研 WebGL2 + 手写 glTF 加载器 + PBR | 1~1.5 周 | 很高（技术分） | 高 | 团队 4~5 人且有强图形开发 |
| `<model-viewer>` / 现成 viewer | 半天 | 低 | 低 | 只做保底 demo |

**推荐 three.js**，理由：

- GLTFLoader、PBR、IBL、阴影、后处理都是现成的，把时间留给“作品”；
- 课程允许第三方库，且你实验一～三已经证明了底层能力，实验四转向“综合应用”是合理的工程选择；
- 仍可保留“自己的东西”：自建展厅几何、自定义材质（全息/剖切/线框渐变）、自定义后期、自己写的交互状态机与 UI。

> 如果坚持自研 WebGL2：把模型压到 1~2 个、只支持 glTF 的静态网格 + PBR，放弃骨骼动画、morph、Draco；否则三周不够。

### ⚠️ `file://` 的两个硬坑（必须提前解决）

1. **ES Module 被 CORS 拦截**：新版 three.js 只发 ESM，`<script type="module">` 直接 `import` 本地文件在 `file://` 下会失败。解决：用 **esbuild 打成 IIFE**（`--format=iife`）成一个普通 `<script>`，或随包提供 `启动.bat` 起本地服务器（推荐双保险）。
2. **`fetch`/XHR 读不了本地 GLB**：`GLTFLoader.load('model.glb')` 在 `file://` 下会失败。解决：把 GLB 转 Base64 写进普通 JS（`window.MODELS.camera = "..."`），用 `GLTFLoader.parse(arrayBuffer, '', ...)` 解析；**每个模型一个 JS，按需注入 `<script>`**，避免一个几十 MB 的巨型文件。

> 这也是为什么旧实验坚持 `assets-data.js`：普通脚本在 `file://` 下可以加载，fetch 不行。新项目沿用同一思路即可。

### 已实测的模型体积（GitHub API 读取）

| 模型 | 体积 | 许可 | 结论 |
| --- | --- | --- | --- |
| DamagedHelmet.glb | **3.60 MB** | 模型 CC BY 4.0，**原贴图 CC BY-NC 4.0** | 体积合适，但 NC 贴图有风险，不建议商用/再分发 |
| Avocado.glb | 7.73 MB | **CC0** | 可用，但作为“展品”不够好看 |
| BoomBox.glb | 10.12 MB | **CC0** | 适合产品可视化 |
| WaterBottle.glb | 8.55 MB | **CC0** | 同上 |
| Sponza（glTF） | **约 50 MB**（bin 9.09 MB + 大量 1K 贴图） | **CryEngine 许可** | **不要用**：体积大 + 许可不适合 |

> 结论：**Khronos 官方示例不是“全是 CC0”**——DamagedHelmet 的贴图是 NC，Sponza 是 CryEngine 协议。选模型时先看模型目录里的 `README.md`/`LICENSE`，并把来源、作者、许可写进报告附录。

## 五、资产管线（把 50MB 压到能双击运行）

推荐工具链（Windows，无需 Blender 也能跑）：

1. **下载**：优先 glTF/GLB；OBJ/FBX 需转换。
2. **体检**：`gltf-transform inspect model.glb` 看面数、贴图、材质、动画。
3. **优化**：`gltf-transform optimize in.glb out.glb --texture-compress webp --texture-size 1024`，必要时 `simplify` 减面（保留轮廓）。
4. **验证**：Khronos glTF Validator（在线/CLI），确认无错误。
5. **Base64 内嵌**：Node 脚本把 GLB 转成 `models/<name>.js`（`window.MODELS[name] = "..."`）。
6. **加载**：`GLTFLoader.parse(base64ToArrayBuffer(...), '', onLoad)`。
7. **预算**：全部模型 Base64 后 **≤ 20 MB**；主角 5~8 万面、1K 贴图；总三角形 ≤ 50 万、draw call ≤ 150。

**不要用 Draco / KTX2**（除非把 wasm 解码器也内嵌）：它们的解码器在 `file://` 下同样要做额外处理，3 周项目不值得。用“减面 + WebP/JPEG 1K”换体积更稳。

## 六、让开源模型“看起来贵”的关键

模型本身只占 30%，剩下 70% 是渲染：

1. **IBL 环境光照**：three.js 的 `RoomEnvironment` + `PMREMGenerator` 就能做出影棚感，不需要外部 HDR 文件；这是“塑料感”和“高级感”的分水岭。
2. **阴影**：每展台一盏 SpotLight + 2048 阴影贴图；地面加接触阴影/AO 贴片，模型才“落地”。
3. **色调映射**：`ACESFilmicToneMapping` + 曝光控制；不加会灰。
4. **材质微调**：扫描件的粗糙度/金属度经常是错的，逐件改；加一点 clearcoat/边缘光。
5. **后期**：Bloom（灯带/高光）、暗角、轻微颗粒；SSAO 可选。
6. **构图**：展台高度、相机 FOV 42~50、三分法、前景遮挡；不要一上来就正交俯视。
7. **动效**：转台缓动、聚焦时相机推拉、爆炸图分段缓动——静态模型也能“活”。

## 七、推荐方案细化：《造物 · 虚拟产品展厅》

### 场景

- **中庭**：程序化生成的清水混凝土展厅（你自己的几何），天窗、格栅、轨道灯；
- **5 个展台**：每台一件 CC0 产品（相机/音箱/台灯/腕表/家具），高度与灯光差异化；
- **灯光预设**：日光（天窗）、黄昏（暖低角）、夜间（聚光 + 灯带）、摄影棚（三点光 + 黑背景）；
- **信息层**：标注热点、参数卡、材质对比、来源与许可。

### 交互

| 输入 | 功能 |
| --- | --- |
| WASD / 方向键 | 第一人称移动 |
| 鼠标拖动 | 环视 |
| 点击展品 / `E` | 聚焦、打开信息卡 |
| `X` | 爆炸图（拆解/组装） |
| `M` | 材质/配色切换 |
| `L` | 展厅灯光预设 |
| `G` | 导览模式（自动巡游） |
| `P` | 拍照模式（隐藏 UI、曝光/焦距） |
| `R` | 复位 |

### 技术亮点（PPT 可单独讲）

1. PBR + IBL 的影棚级材质；
2. 自建展厅的程序化几何与灯光设计；
3. 模型资产管线（减面/贴图压缩/Base64 内嵌/许可审计）；
4. 爆炸图（按部件法线方向位移 + 缓动）；
5. 自定义剖切/全息 shader（选一个做“自己的技术”）；
6. 后期链（Bloom/ACES/暗角）；
7. 性能与自动化测试。

| 风险 | 对策 |
| --- | --- |
| “模型不是你做的” | PPT 明确“资产管线 + 自建展厅 + 渲染/交互”，并展示优化前后对比 |

| 现场演示 | 录屏 + 低画质档 + 本地服务器备份 |

## 九、下一步（建议先做 1 天 spike）

1. 选 1 件 CC0 模型（推荐 Poly Haven 的产品/道具，或 Khronos 的 BoomBox）；
2. 用 `gltf-transform` 压到 2MB 以内；
3. esbuild 打 three.js IIFE，Base64 内嵌，双击 `index.html` 能看到带 IBL + 阴影的转台；
4. 用 Playwright 截图，确认 `file://` 无报错。

这个 spike 通过，整条路线就成立了；通不过就退回“自研 WebGL2 + OBJ”或“本地服务器”方案。
